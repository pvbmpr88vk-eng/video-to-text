# ТЗ-01: Извлечение аудиодорожки из видео

**Проект:** video-to-text  
**Этап:** 1 из 6  
**Архитектура:** монолит (Python)  
**Версия ТЗ:** 1.0  
**Дата:** 2026-05-19  

---

## 1. Цель этапа

Реализовать модуль извлечения аудио из видеофайла (и при необходимости из контейнеров с одной аудиодорожкой) в **стандартизированном формате**, пригодном для последующей передачи в speech-to-text (этап 2) без доработки кодека на стороне STT.

Этап **не включает** распознавание речи, работу с ИИ, Telegram и загрузку по ссылке.

---

## 2. Контекст в общей цепочке

```
[Видео / аудиофайл] → [ТЗ-01: extract_audio] → [WAV/MP3] → [ТЗ-02: STT] → [Текст] → [ТЗ-03: саммари] → [ТЗ-04: TG-бот]
```

ТЗ-01 задаёт **контракт выходного файла**, чтобы этап 2 не зависел от исходного контейнера (MP4, MOV, MKV и т.д.).

---

## 3. Границы scope

### В scope

- Локальный файл: путь к видео/аудио на диске.
- Извлечение аудиодорожки через **FFmpeg** (внешняя зависимость).
- Нормализация параметров: частота дискретизации, каналы, кодек, битрейт (для MP3).
- Валидация входа (существование файла, наличие аудиопотока).
- CLI-команда и вызываемая Python-функция для использования из монолита.
- Логирование этапов и понятные ошибки.
- Сохранение результата в каталог `output/audio/` (или путь из аргумента).

### Вне scope (следующие этапы)

- Скачивание видео по URL (этап 5).
- STT / локальные или облачные модели (этап 2).
- Саммаризация текста (этап 3).
- Telegram-бот (этап 4).
- Параллельная обработка очереди, веб-UI, БД.

## 4. Требования к выходному аудио

Целевой профиль согласован с типичными STT (Whisper, faster-whisper, облачные API):

| Параметр | Значение по умолчанию | Обоснование |
|----------|----------------------|-------------|
| Контейнер | `.wav` | Без потерь, минимум артефактов для STT |
| Кодек | PCM 16-bit (`pcm_s16le`) | Стандарт для Whisper |
| Sample rate | **16000 Hz** | Оптимально для большинства STT-моделей |
| Каналы | **1 (mono)** | Меньше размер, достаточно для речи |
| Длительность | = длительности исходного аудиопотока | Без обрезки, если не задан `--max-duration` |

### Опциональный профиль (флаг CLI)

| Параметр | Значение |
|----------|----------|
| Формат | MP3 |
| Bitrate | 64–128 kbps (по умолчанию **96 kbps**) |
| Sample rate | 16000 Hz |
| Каналы | mono |

MP3 — для уменьшения объёма при отправке на удалённый STT; WAV — для локального пайплайна и максимального качества.

---

## 5. Поддерживаемые входные форматы

Через FFmpeg (без жёсткого whitelist на первой итерации):

- Видео: `mp4`, `mov`, `mkv`, `avi`, `webm`
- Аудио: `mp3`, `wav`, `m4a`, `aac`, `ogg`, `flac`

**Поведение при отсутствии аудиопотока:** ошибка с кодом `NO_AUDIO_STREAM`, сообщение пользователю.

**Поведение при нескольких аудиодорожках:** по умолчанию первая дорожка; опционально `--audio-track-index N`.

## 6. Функциональные требования

### FR-01. Извлечение из файла

- Вход: абсолютный или относительный путь к файлу.
- Выход: путь к созданному аудиофайлу.
- Имя выходного файла: `{stem}_{timestamp}.wav` или `.mp3`.

### FR-02. CLI

```bash
python -m app extract-audio INPUT_PATH [--format wav|mp3] [--output-dir DIR] [--audio-track-index N] [--max-duration SEC]
```

Коды возврата:

| Код | Смысл |
|-----|--------|
| 0 | Успех |
| 1 | Файл не найден |
| 2 | Нет аудиопотока |
| 3 | Ошибка FFmpeg / конвертации |
| 4 | Некорректные аргументы |

### FR-03. Программный API (для монолита)

```python
def extract_audio(
    input_path: str | Path,
    *,
    output_dir: Path | None = None,
    format: Literal["wav", "mp3"] = "wav",
    audio_track_index: int = 0,
    max_duration_sec: float | None = None,
) -> Path:
    """Возвращает Path к созданному файлу. Исключения — доменные (см. раздел 8)."""
```

### FR-04. Метаданные результата

После успеха модуль возвращает (или пишет в sidecar JSON рядом с файлом) минимум:

- `duration_sec`
- `sample_rate`
- `channels`
- `format`
- `source_path`
- `created_at` (ISO 8601)

Нужно для этапа 2 (оценка стоимости/времени STT).

### FR-05. Проверка FFmpeg

При старте: проверка `ffmpeg` и `ffprobe` в `PATH`. Если нет — явная инструкция установки (macOS: `xcode-select` уже есть; при необходимости `brew install ffmpeg`).

## 7. Нефункциональные требования

| ID | Требование |
|----|------------|
| NFR-01 | Без GPU; только CPU + FFmpeg |
| NFR-02 | Обработка файла до **2 часов** без падения (память — потоковая через FFmpeg, без загрузки всего видео в RAM) |
| NFR-03 | Время извлечения: ориентир **≤ 0.3 × длительности** ролика на типичном MacBook Air (зависит от кодека источника) |
| NFR-04 | Логи: `INFO` — этапы; `ERROR` — stderr FFmpeg (обрезать до 2 КБ в логе) |
| NFR-05 | Конфигурация через `.env` не обязательна на этапе 1; достаточно аргументов CLI и констант в `config.py` |
| NFR-06 | Код — type hints, Python **≥ 3.11** |

## 10. Пример FFmpeg-команд (референс)

**WAV (по умолчанию):**

```bash
ffmpeg -y -i "{input}" -map 0:a:{track_index} -vn \
  -acodec pcm_s16le -ar 16000 -ac 1 \
  "{output}.wav"
```

**MP3:**

```bash
ffmpeg -y -i "{input}" -map 0:a:{track_index} -vn \
  -acodec libmp3lame -ar 16000 -ac 1 -b:a 96k \
  "{output}.mp3"
```

**Длительность (опционально):** добавить `-t {max_duration_sec}`.

Перед конвертацией — `ffprobe` для проверки наличия `codec_type=audio`.

## 11. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Файл не существует | `FileNotFoundError` / exit 1 |
| Нет аудиодорожки | `NoAudioStreamError` / exit 2 |
| FFmpeg вернул ≠ 0 | `FFmpegError` с фрагментом stderr / exit 3 |
| Недостаточно места на диске | `OSError`, сообщение с требуемым объёмом |
| Повреждённый файл | `FFmpegError`, лог полного stderr |

## 13. Зависимости для этапа 2 (информативно)

Выход ТЗ-01 должен быть совместим с:

- **faster-whisper** (локально, CPU/CUDA опционально позже)
- **OpenAI Whisper API** / аналоги (ограничения по размеру файла → MP3 профиль)
- Серверный разворот без GPU: 16 kHz mono WAV/MP3 — стандартный вход

Размер файла для планирования: WAV ≈ `duration_sec × 16000 × 2` байт; MP3 ≈ `duration_sec × 12_000` байт (96 kbps).
