# ТЗ-04: Telegram-бот (интерфейс к пайплайну 1→2→3)

**Проект:** video-to-text  
**Этап:** 4 из 6  
**Архитектура:** монолит (Python)  
**Зависит от:** [ТЗ-01](TZ-01-audio-extraction.md), [ТЗ-02](TZ-02-stt.md), [ТЗ-03](TZ-03-summary.md)  
**Версия ТЗ:** 1.0  
**Дата:** 2026-05-19  

---

## 1. Цель этапа

Дать пользователю **Telegram-интерфейс** к уже реализованному локальному пайплайну:

```
[Видео / аудио в Telegram] → [ТЗ-01] → [ТЗ-02] → [ТЗ-03] → [ответы в чат]
```

Пользователь отправляет файл (или ссылку — только в **ТЗ-05**, документ в разработке), получает статус обработки и результат: **транскрипт** (файлом), **саммари** (текст + файл `.summary.md`), **тезисы** (сообщения в чат).

Обработка остаётся **на той же машине**, что CLI: faster-whisper (CPU), Ollama (локально). Данные **не отправляются** в облачные STT/LLM API.

Этап **не включает:** скачивание по URL (ТЗ-05), веб-UI, мультиарендный SaaS, оплату, админ-панель, хранение истории в БД.

## 2. Контекст в общей цепочке

```
[Пользователь в Telegram]
        │
        ▼
┌───────────────────┐
│  ТЗ-04: bot       │  long polling, очередь 1 job
│  app/telegram/    │
└─────────┬─────────┘
          │ вызывает существующие API
          ▼
   extract_audio() → transcribe_audio() → summarize_transcript()
          │                    │                    │
          ▼                    ▼                    ▼
   output/audio/      output/transcripts/   output/summaries/
```

**Референс CLI (уже работает):**

```bash
python -m app process "111.mp4" --language ru --summarize
```

Бот должен выполнять **эквивалент** этой цепочки для принятого файла, с прогрессом в чате.

**Референс-кейс приёмки (длинный):** `111.mp4` (~48 мин) — прогон через **CLI**; через бота v1 — только если файл ≤ лимита Telegram (см. п. 5.3) или после ТЗ-05 / Local Bot API.

## 3. Границы scope

### В scope (v1)

- Один бот, один процесс, **long polling** (`getUpdates`).
- Приём **видео**, **аудио**, **документов** (контейнеры из п. 5.1) от разрешённых пользователей.
- Пайплайн по умолчанию: **извлечение аудио → STT → саммари** (`--summarize` включён).
- Команды: `/start`, `/help`, `/status`, `/cancel`.
- Режим «только транскрипт»: `/text` или кнопка «Без саммари» (см. FR-04).
- Язык распознавания и саммари: **`ru`** по умолчанию; опция `/lang en` (v1) или аргумент в `.env`.
- Очередь задач: **одна активная задача** на инстанс бота (как в ТЗ-03 для Ollama/STT на 8 GB RAM).
- Скачивание файла из Telegram → `output/telegram/inbox/`.
- Промежуточные статусы в чате (редактируемое сообщение или цепочка коротких сообщений).
- Отправка результатов: `.summary.md`, `.txt` транскрипта, тезисы текстом (с разбиением).
- Конфиг: текстовый файл `telegram-bot.access.txt` (токен + `user_id`); опционально env / `.env`.
- CLI: `python -m app bot` (или подкоманда `telegram`).
- Тесты: handlers с mock `python-telegram-bot`; утилита разбиения сообщений; без реального токена в CI.

### Вне scope (v2+)

- Скачивание YouTube / Google Drive / произвольных URL (**ТЗ-05**).
- Webhook + HTTPS, reverse proxy (v1.1 на VPS).
- [Local Bot API Server](https://core.telegram.org/bots/api#using-a-local-bot-api-server) (файлы >20 MB) — v1.1, документировать.
- Несколько параллельных джобов, Redis/RQ, Celery, PostgreSQL.
- Inline-режим, группы с несколькими админами, платежи.
- Редактирование/перевод транскрипта в боте.
- Push в Notion / email / Slack.

### В scope v1.1 (не блокирует приёмку v1)

- Webhook-режим (`TELEGRAM_WEBHOOK_URL`).
- Inline-клавиатура: «Полный цикл / Только текст / Отмена».
- Отправка `.theses.json` файлом.
- Команда `/last` — пути к последним артефактам на диске (для отладки, только whitelist).

## 4. Выбор стека и обоснование

### 4.1. Библиотека: `python-telegram-bot` ≥21

| Критерий | PTB 21+ | aiogram 3 |
|----------|---------|-----------|
| Документация / примеры | много | много |
| Async | да | да |
| Скачивание файлов | `get_file` + `download_to_drive` | аналог |
| Интеграция в монолит | проще для синхронного STT в `asyncio.to_thread` | аналог |

**Решение:** `python-telegram-bot` v21+, `Application` + `CommandHandler` + `MessageHandler`.

### 4.2. Выполнение тяжёлой работы

STT и Ollama **блокируют CPU/RAM** и не должны выполняться в event loop.

| Компонент | Способ |
|-----------|--------|
| Скачивание файла из TG | async (`download_to_drive`) |
| `extract_audio`, `transcribe_audio`, `summarize_transcript` | `asyncio.to_thread(...)` или `ProcessPoolExecutor(max_workers=1)` |
| Очередь | `asyncio.Queue` + один worker-task |

**Правило:** не запускать **STT и summarize одновременно**; последовательно, как в README этапа 3.

### 4.3. Режим развёртывания v1

| Среда | Рекомендация |
|-------|----------------|
| MacBook 8 GB (разработка) | `brew services start ollama`, бот в терминале, polling |
| VPS без GPU | тот же монолит; предупреждение о времени STT |
| Продакшен | один инстанс бота + Ollama + FFmpeg на одном хосте |

Webhook не обязателен в v1 (удобнее локальная разработка без публичного URL).

### 4.4. Доступ к боту: текстовый документ (токен и user id)

Секреты бота хранятся **локально в текстовом файле** в корне проекта (не в git). Это основной способ конфигурации для разработки и личного использования; переменные окружения и `.env` — опциональное переопределение.

| Файл | В git | Назначение |
|------|-------|------------|
| `telegram-bot.access.example.txt` | да | шаблон без реальных значений |
| `telegram-bot.access.txt` | **нет** | рабочий файл с токеном и `user_id` |
| `Токен и ссылка бота .rtf` (если есть) | **нет** | устаревший формат; перенести значения в `.txt` |

**Путь по умолчанию:** `{PROJECT_ROOT}/telegram-bot.access.txt`  
Переопределение: переменная `TELEGRAM_ACCESS_FILE=/абсолютный/путь.txt`.

#### Формат файла

UTF-8, одна пара `ключ=значение` на строку. Строки с `#` в начале — комментарии. Пустые строки игнорируются.

```text
# Telegram — доступ к боту (не коммитить с реальными данными)
BOT_TOKEN=123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ALLOWED_USER_IDS=987654321
BOT_USERNAME=@my_video_to_text_bot
BOT_LINK=https://t.me/my_video_to_text_bot
```

| Ключ | Обязательно | Описание |
|------|-------------|----------|
| `BOT_TOKEN` | да | токен от [@BotFather](https://t.me/BotFather) |
| `ALLOWED_USER_IDS` | да | ваш числовой `user_id` Telegram (один или несколько через запятую) |
| `BOT_USERNAME` | нет | `@имя_бота` — для справки в `/help` |
| `BOT_LINK` | нет | ссылка `https://t.me/...` — для справки |

**Как узнать свой `user_id`:** написать боту [@userinfobot](https://t.me/userinfobot) или [@getmyid_bot](https://t.me/getmyid_bot); в ответ придёт числовой id.

#### Порядок загрузки при старте `python -m app bot`

1. Прочитать `telegram-bot.access.txt` (если файл существует).
2. Переменные окружения **перекрывают** файл: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_IDS`.
3. Опционально `.env` (как в остальном проекте) — с теми же именами переменных.

Если после слияния нет `BOT_TOKEN` / `TELEGRAM_BOT_TOKEN` → exit **7** с текстом: «Создайте `telegram-bot.access.txt` из `telegram-bot.access.example.txt`».

Модуль `app/telegram/credentials.py`: парсинг файла, валидация (токен содержит `:`; id — только цифры и запятые).

## 5. Требования к входным данным

### 5.1. Поддерживаемые типы сообщений

| Тип в Telegram | Обработка |
|----------------|-----------|
| `video` | скачать, сохранить расширение из MIME |
| `audio` | скачать |
| `document` | если MIME `video/*`, `audio/*` или расширение `.mp4`, `.mov`, `.mkv`, `.webm`, `.m4a`, `.wav`, `.mp3`, `.ogg` |
| `voice` | **v1:** принять как OGG/Opus → FFmpeg конвертирует при extract (или отдельный путь `transcribe` напрямую) |
| Текст со ссылкой | **отклонить** с подсказкой «ссылки — в следующем обновлении (ТЗ-05)» |
| Фото, стикеры | вежливый отказ |

### 5.2. Валидация

- Пустой `file_id` → ошибка handler.
- Неизвестный MIME → «формат не поддерживается».
- Пользователь не в whitelist → «доступ запрещён» (без деталей).
- Уже есть активная задача → «подождите, идёт обработка предыдущего файла» + `/status`.

### 5.3. Лимиты Telegram и проекта

| Параметр | Лимит | Поведение |
|----------|-------|-----------|
| Размер файла через **стандартный** Bot API | **20 MB** | до скачивания: `getFile`; если `file_size > 20_000_000` → сообщение с объяснением и отсылкой к ТЗ-05 / сжатию / Local Bot API |
| Длительность медиа | до **2 ч** | как ТЗ-02: предупреждение, не блокировать |
| Активных задач | **1** | очередь из 1 pending (v1) или отказ второму |
| Длина исходящего сообщения | **4096** символов | разбиение (п. 6.3) |
| RAM 8 GB | STT затем summarize | не параллелить этапы |

**Важно:** референс `111.mp4` (~48 мин) обычно **>20 MB** — полный прогон через бота в v1 может быть недоступен без ТЗ-05 или Local Bot API. Приёмка v1 — на **коротком** файле (3–10 мин, <20 MB).

## 6. Требования к выходным данным (ответы в Telegram)

### 6.1. Порядок отправки после успеха

1. **Итоговое сообщение** (кратко): длительность, модели STT/LLM, время обработки.
2. **Саммари** — текст из поля `summary` + список тезисов (первые N, см. п. 6.3).
3. **Файл** `*.summary.md` (`send_document`).
4. **Файл** `*.txt` транскрипта (`send_document`).
5. Опционально v1.1: `*.theses.json`.

При ошибке на этапе 2 — отправить то, что есть (например, только аудио не отправлять; при ошибке этапа 3 — транскрипт всё равно отдать, если STT успешен).

### 6.2. Формат текстового саммари в чате

```text
📋 Краткий пересказ
…

📌 Тезисы
1. …
2. …

✅ Действия
• [ ] …
```

Markdown: **v1 — plain text** (без `parse_mode=MarkdownV2`), чтобы не ломать спецсимволы из STT. v1.1 — опционально `HTML` с экранированием.

### 6.3. Разбиение длинных сообщений

Функция `split_telegram_message(text, limit=4096)`:

- резать по границам абзаца (`\n\n`), затем строки (`\n`);
- не разрывать UTF-8 surrogate pairs;
- нумеровать части: `(1/3)`, `(2/3)` в начале, если частей >1;
- для тезисов: не более **15** пунктов в чате; полный список — в `.summary.md` / `.theses.json`.

Лимит Telegram на caption/document description — не использовать для длинного текста; только отдельные сообщения и файлы.

### 6.4. Сообщения о прогрессе

| Этап | Текст (пример) |
|------|----------------|
| Принято | «Файл получен (12.4 MB). Ставлю в очередь…» |
| Скачано | «Скачано. Извлекаю аудио…» |
| ТЗ-01 готово | «Аудио готово (16:32). Распознаю речь… это может занять десятки минут» |
| ТЗ-02 готово | «Транскрипт готов (42k символов). Делаю саммари…» |
| ТЗ-03 готово | «Готово за 47 мин» |
| Ошибка | этап + краткая причина + что проверить (Ollama, FFmpeg) |

Обновление: `edit_message_text` одного статус-сообщения не чаще **1 раз в 30 с** (лимиты Telegram + шум).

## 7. Функциональные требования

### FR-01. Запуск бота

```bash
python -m app bot [-v]
```

| Источник | Описание |
|----------|----------|
| `telegram-bot.access.txt` | основной: `BOT_TOKEN`, `ALLOWED_USER_IDS` (см. п. 4.4) |
| `TELEGRAM_BOT_TOKEN` | env, перекрывает файл |
| `TELEGRAM_ALLOWED_USER_IDS` | env, перекрывает файл; пусто после загрузки → **запрет всем** |
| `TELEGRAM_ACCESS_FILE` | путь к альтернативному `.txt` |
| `-v` | DEBUG логи |

При старте:

1. Загрузить credentials из `.txt` + env; проверить токен (`getMe`).
2. Проверить FFmpeg (как CLI).
3. Если режим с саммари: `GET {OLLAMA_HOST}/api/tags` — иначе предупреждение «саммари отключится».
4. Вывести в лог: whitelist, модели STT/LLM.

Код выхода CLI: `0` — штатная остановка; `7` — ошибка конфигурации/запуска бота (новый код, не пересекается с 1–6).

### FR-02. Команды

| Команда | Действие |
|---------|----------|
| `/start` | приветствие, краткая инструкция, лимит 20 MB, язык `ru` |
| `/help` | форматы, время ожидания, команды, ссылка на README |
| `/status` | состояние текущей задачи: idle / downloading / extract / stt / summary / error |
| `/cancel` | отмена **ожидающей** задачи или запрос прерывания текущей (best-effort; STT может не прерваться мгновенно) |
| `/text` | следующий файл — **без** саммари (только до этапа 2) |
| `/full` | сброс режима: снова полный цикл (по умолчанию) |

### FR-03. Обработчик медиа

Псевдокод:

```python
async def on_media(update, context):
  user_id = update.effective_user.id
  if not is_allowed(user_id): ...
  job = await queue.submit(build_job_from_update(update))
  await job.run_pipeline()  # в thread pool
```

`build_job_from_update`:

- `chat_id`, `message_id`, `user_id`, `file_id`, `file_size`, `local_path`, `mode=full|text_only`, `language=ru`.

### FR-04. Пайплайн задачи (`PipelineJob`)

| Шаг | API | Артефакт |
|-----|-----|----------|
| 1 | скачать в `output/telegram/inbox/{chat_id}_{ts}.ext` | исходник |
| 2 | `extract_audio(path, output_dir=DEFAULT_OUTPUT_DIR)` | WAV |
| 3 | `transcribe_audio(wav, parallel=True, workers=…)` | `.json`, `.txt` |
| 4 | если `mode=full`: `summarize_transcript(json)` | `.summary.md`, `.theses.json` |
| 5 | отправить в чат | — |

Параметры STT для бота (зафиксировать в `config.py` или `.env`):

| Параметр | Значение v1 |
|----------|-------------|
| `WHISPER_MODEL` | `small` (как проект) |
| `parallel` | `true` |
| `workers` | `min(4, cpu_count-1)` |
| `language` | `ru` |

### FR-05. Очередь и конкурентность

- Глобально **один** `asyncio.Lock` на выполнение пайплайна.
- Второй файл во время обработки: ответ «Занято. /status»; опционально поставить в очередь max 1 (v1.1).
- Файлы на диске **не удалять** автоматически (как CLI); очистка — вручную или cron вне scope.

### FR-06. Безопасность

| Требование | Реализация |
|------------|------------|
| Секреты | `telegram-bot.access.txt` локально; **не** в git (`.gitignore`: `.env`, `telegram-bot.access.txt`, `*бота*.rtf`) |
| Whitelist | обязателен в проде; без списка — бот не обрабатывает медиа |
| Логи | не писать полный транскрипт в INFO; только длины и пути |
| Входные пути | только файлы, скачанные ботом; path traversal запрещён |
| Rate limit | не более **10** входящих медиа в час на `user_id` (простой счётчик в памяти, v1) |

### FR-07. Обработка ошибок → пользователь

| Источник | Сообщение пользователю |
|----------|------------------------|
| `FFmpegNotFoundError` | «На сервере не установлен FFmpeg» |
| `NoAudioStreamError` | «В файле нет звука» |
| `ModelNotAvailableError` | «Модель распознавания не загружена» |
| `TranscriptionError` | «Ошибка распознавания» + retry позже |
| `SummaryAPIError` / Ollama down | «Транскрипт готов, саммари не удалось: Ollama недоступна» + файл txt |
| Файл >20 MB | «Файл слишком большой для Telegram Bot API (20 MB)…» |
| Не в whitelist | «У вас нет доступа к этому боту» |

Внутренние traceback — только в лог (`-v`).

## 9. Сценарии приёмки (DoD)

### A — конфигурация

- [ ] Без `telegram-bot.access.txt` и без env-токена → exit `7`, подсказка скопировать `.example.txt`.
- [ ] С `BOT_TOKEN` в `.txt`, пустой `ALLOWED_USER_IDS` → бот отвечает на `/start`, но **отклоняет** медиа.
- [ ] В `.txt` указан тестовый `user_id` → медиа принимается.
- [ ] Env `TELEGRAM_BOT_TOKEN` перекрывает значение из файла.

### B — короткий файл (<20 MB, 3–10 мин)

- [ ] Отправить MP4 → статусы по этапам → `.txt` + `.summary.md` в чате.
- [ ] Тезисы приходят хотя бы одним сообщением ≤4096 символов.

## 13. Риски и ограничения

| Риск | Митигация |
|------|-----------|
| STT 48 мин на CPU — часы ожидания | статусы, `/status`; realistic ETA в /help |
| 8 GB RAM: OOM | один job; не parallel STT+summarize |
| Telegram 20 MB | явное сообщение; ТЗ-05 |
| Плохое саммари 3B | дисклеймер в /help; пользователь читает `.md` |
| Бот публичный без whitelist | запрет по умолчанию |
| Зависший STT | `/cancel` best-effort; перезапуск процесса |
| Спецсимволы в STT ломают Markdown | plain text v1 |
