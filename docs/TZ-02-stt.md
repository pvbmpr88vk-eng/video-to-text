# ТЗ-02: Распознавание речи (STT)

**Проект:** video-to-text  
**Этап:** 2 из 6  
**Архитектура:** монолит (Python)  
**Зависит от:** [ТЗ-01](TZ-01-audio-extraction.md) (WAV/MP3 16 kHz mono)  
**Версия ТЗ:** 1.0  
**Дата:** 2026-05-19  

---

## 1. Цель этапа

Принять **аудиофайл** из этапа 1 и получить **сырую текстовую транскрипцию** с опциональными таймкодами по сегментам.

Распознавание выполняется **локально на CPU** без собственного GPU, чтобы не нести затраты на видеокарту; развёртывание на сервере (этап инфраструктуры) использует тот же движок.

Этап **не включает:** тезисный разбор и пересказ (ТЗ-03), Telegram-бот (ТЗ-04), загрузку видео по ссылке (ТЗ-05).

---

## 2. Контекст в общей цепочке

```
[Видео] → [ТЗ-01: extract_audio] → [WAV/MP3] → [ТЗ-02: transcribe] → [.txt + .json]
                                                              ↓
                                                    [ТЗ-03: summary LLM]
                                                              ↓
                                                    [ТЗ-04: Telegram-бот]
```

**Входной контракт от ТЗ-01:**

| Параметр | Ожидаемое значение |
|----------|-------------------|
| Формат | `.wav` (основной) или `.mp3` |
| Sample rate | 16 000 Hz |
| Каналы | 1 (mono) |
| Sidecar | `{файл}.wav.meta.json` с `duration_sec` |

Этап 2 **не перекодирует** аудио; при несовпадении профиля — предупреждение в логе, но обработка допускается (faster-whisper принимает разные форматы).

## 3. Границы scope

### В scope

- Локальный файл: путь к WAV/MP3 (результат `extract-audio` или эквивалент).
- Движок STT: **faster-whisper** (обёртка над CTranslate2 / Whisper).
- Режим: **CPU**, `compute_type=int8` по умолчанию.
- Модели Whisper: `tiny`, `base`, `small`, `medium` (через аргумент; по умолчанию `small`).
- Язык: автоопределение или явный (`--language ru`).
- VAD-фильтр (тишина/шум) — включён по умолчанию.
- Выход: plain text (`.txt`) и структурированный JSON (`.json`) с сегментами.
- CLI `transcribe` и программный API `transcribe_audio()`.
- Первая загрузка весов модели с Hugging Face Hub (кэш на диске).
- Логирование этапов (загрузка модели, старт/конец, ошибки).
- Юнит-тесты с mock модели; интеграционный тест — опционально, короткий sample.

### Вне scope (следующие этапы / v2)

- Облачный STT (OpenAI Whisper API, AssemblyAI и т.д.) — отдельный backend в будущем.
- Саммаризация, тезисы, пересказ (ТЗ-03).
- Telegram, диалоговое окно (ТЗ-04).
- Скачивание медиа по URL (ТЗ-05).
- GPU/CUDA (опционально v2.1 на сервере с видеокартой).
- Потоковая транскрипция в реальном времени.
- Диаризация (кто говорит).
- Правка пунктуации отдельной LLM (может войти в ТЗ-03).
- Очередь задач, веб-UI, БД.

### В scope v1.1 (желательно, не блокирует приёмку v1)

- CLI-команда `process`: `extract-audio` + `transcribe` одной цепочкой.
- Прогресс в логе (% или сегменты) для длинных файлов (>30 мин).
- Чтение `duration_sec` из sidecar ТЗ-01 для оценки времени STT.
- **Параллельная транскрипция по чанкам (п. 4)** — см. раздел 4.4.

## 4. Выбор модели и обоснование

### 4.1. Движок: faster-whisper

| Критерий | faster-whisper | openai-whisper (оригинал) | Облачный API |
|----------|----------------|---------------------------|--------------|
| GPU | не обязателен | желателен | не нужен локально |
| Стоимость | бесплатно | бесплатно | платно за минуту |
| Офлайн | да | да | нет |
| Скорость на CPU | высокая (CTranslate2) | низкая | N/A |
| Приватность | данные локально | данные локально | отправка на сервер |

**Решение:** faster-whisper для монолита v1.

### 4.2. Размер модели по умолчанию: `small`

| Модель | RAM (ориентир) | Качество RU | Скорость CPU (48 мин аудио) |
|--------|----------------|-------------|-----------------------------|
| `tiny` | ~1 GB | низкое | ~10–20 мин |
| `base` | ~1.5 GB | среднее | ~15–30 мин |
| **`small`** | **~2 GB** | **хорошее** | **~25–50 мин** |
| `medium` | ~5 GB | очень хорошее | ~60–120 мин |

**Решение:** `small` — баланс качества русской речи и времени на MacBook Air без GPU.

Для тестов и отладки: `tiny` или `base`. Для продакшена на сервере CPU: `small` или `medium`.

### 4.3. Параметры inference (по умолчанию)

| Параметр | Значение | Комментарий |
|----------|----------|-------------|
| `device` | `cpu` | без CUDA |
| `compute_type` | `int8` | быстрее на CPU, небольшая потеря точности |
| `beam_size` | `5` | компромисс скорость/качество |
| `vad_filter` | `true` | пропуск длинных пауз |
| `language` | `None` (auto) или `ru` | флаг CLI |

### 4.4. Ускорение: параллельная нарезка на CPU (п. 4)

Цель — сократить wall-time STT на многоядерном CPU **без GPU и без облака**, за счёт обработки нескольких фрагментов аудио параллельно.

> **Ограничение:** для файла ~48 мин это **не даёт 2–3 минуты** суммарно; реалистичное ускорение **~2–4×** (ориентир **15–25 мин** вместо 25–50 мин при `small`). Для цели 2–3 минуты см. облачный STT или GPU (вне этого пункта).

#### Алгоритм

1. Входной WAV/MP3 режется на чанки фиксированной длительности (по умолчанию **10 мин**).
2. Каждый чанк транскрибируется в **отдельном worker-процессе** (`multiprocessing`), со своим экземпляром модели или через пул (см. RAM).
3. Смещения таймкодов в сегментах сдвигаются на `chunk_index × chunk_duration_sec`.
4. Сегменты и текст **склеиваются** в порядке возрастания `start`.
5. Итоговые `.txt` / `.json` — как при обычном `transcribe`.

#### Параметры (CLI / config)

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--parallel` | `false` | включить параллельный режим |
| `--chunk-minutes` | `10` | длина чанка в минутах |
| `--workers` | `min(4, cpu_count-1)` | число параллельных процессов |

#### Нарезка

- Инструмент: **FFmpeg** (`-ss`, `-t`) или нарезка через `pydub` / чтение с offset — предпочтительно FFmpeg для единообразия с ТЗ-01.
- Временные файлы чанков: `output/transcripts/.chunks/{basename}/chunk_000.wav` (каталог в `.gitignore`).
- Удаление временных чанков после успеха — по умолчанию **да** (`--keep-chunks` для отладки).

#### Склейка сегментов

```python
segment.start += chunk_index * chunk_duration_sec
segment.end   += chunk_index * chunk_duration_sec
```

Текст: `parts = [chunk.text for chunk in sorted_chunks]` → `" ".join(parts)`.

На границах чанков возможен разрыв слова/фразы — **допустимо в v1.1**; в v1.2 — перекрытие (overlap) 2–5 с и дедупликация.

#### RAM и workers

| workers | Модель `small` (ориентир RAM) | Рекомендация |
|---------|------------------------------|--------------|
| 1 | ~2 GB | режим по умолчанию (v1) |
| 2 | ~4 GB | MacBook Air 8 GB — осторожно |
| 4 | ~8 GB | только при ≥16 GB RAM |

При нехватке памяти — автоматически снизить `workers` или откат на последовательный режим с предупреждением в логе.

#### API (расширение)

```python
def transcribe_audio(
    audio_path: str | Path,
    *,
    ...
    parallel: bool = False,
    chunk_minutes: float = 10.0,
    workers: int | None = None,
) -> TranscriptionResult:
```

#### Критерии готовности (п. 4)

- [ ] `--parallel` на `111.wav` (~48 мин) быстрее последовательного режима **≥1.5×**.
- [ ] Итоговый `duration_sec` и число сегментов согласованы с длиной аудио (±2 с).
- [ ] Таймкоды в JSON монотонно возрастают, без отрицательных значений.
- [ ] Временные чанки удаляются после успеха.
- [ ] При `workers=1` результат совпадает с не-параллельным режимом (±текстовые отличия Whisper на границах).

#### Риски п. 4

| Риск | Митигация |
|------|-----------|
| OOM при 4 workers | лимит `workers`, мониторинг RAM |
| Дублирование загрузки модели в каждом процессе | допустимо в v1.1; shared model — v1.2 |
| Разрыв фраз на стыке чанков | overlap в v1.2; документировать |
| Два `transcribe --parallel` одновременно | запрет в документации |

## 5. Требования к входным данным

### 5.1. Поддерживаемые форматы

`.wav`, `.mp3`, `.m4a`, `.flac`, `.ogg` — через faster-whisper / av.

**Рекомендуемый вход:** WAV 16 kHz mono из ТЗ-01.

### 5.2. Ограничения

| Параметр | Лимит v1 | Поведение при превышении |
|----------|----------|--------------------------|
| Длительность | до **2 часов** | предупреждение; обработка не блокируется |
| Размер файла | ~500 MB (WAV 2 ч) | зависит от RAM; документировать |
| Одновременные задачи | 1 процесс | не запускать два `transcribe` на одну модель |

**Референс-кейс проекта:** `111.mp4` → WAV **48 мин**, **88 MB** — должен обрабатываться без падения.

## 6. Требования к выходным данным

### 6.1. Каталог

`output/transcripts/` (или `--output-dir`).

Имя файлов: `{stem}_{timestamp}.txt` / `.json` (тот же basename, что у аудио после extract).

### 6.2. Файл `.txt`

- Кодировка: UTF-8.
- Содержимое: сплошной текст, сегменты склеены через пробел.
- Завершающий перевод строки в конце файла.

### 6.3. Файл `.json`

```json
{
  "text": "полный текст транскрипции",
  "language": "ru",
  "duration_sec": 2886.592,
  "model": "small",
  "source_path": "/absolute/path/to/audio.wav",
  "created_at": "2026-05-19T14:00:00+00:00",
  "segments": [
    { "start": 0.0, "end": 4.2, "text": "фрагмент речи" }
  ]
}
```

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `text` | да | полный текст |
| `language` | да | код ISO (detected или заданный) |
| `duration_sec` | да | длительность по модели |
| `model` | да | имя модели (`small`, …) |
| `source_path` | да | абсолютный путь к аудио |
| `created_at` | да | ISO 8601 UTC |
| `segments` | если не `--no-segments` | массив с `start`, `end`, `text` (секунды, float) |

`start` / `end` — секунды от начала файла; нужны для ТЗ-03 (цитаты, навигация) и субтитров в будущем.

## 7. Функциональные требования

### FR-01. Транскрипция файла

- Вход: путь к аудио.
- Выход: `TranscriptionResult` с путями к `.txt` и `.json`.
- Пустые сегменты (тишина) не попадают в текст.

### FR-02. CLI

```bash
python -m app transcribe AUDIO_PATH \
  [--model small|tiny|base|medium] \
  [--language ru|en|...] \
  [--output-dir DIR] \
  [--no-segments] \
  [--parallel] \
  [--chunk-minutes 10] \
  [--workers 4] \
  [--keep-chunks] \
  [-v]
```

Коды возврата:

| Код | Смысл |
|-----|--------|
| 0 | Успех |
| 1 | Аудиофайл не найден |
| 4 | Некорректные аргументы / неподдерживаемый формат |
| 5 | Ошибка STT: нет зависимостей, модель не загрузилась, сбой inference |

### FR-03. Программный API

```python
def transcribe_audio(
    audio_path: str | Path,
    *,
    output_dir: Path | None = None,
    model_size: str = "small",
    language: str | None = None,
    with_segments: bool = True,
) -> TranscriptionResult:
    """Возвращает TranscriptionResult. Исключения: FileNotFoundError,
    ValueError, ModelNotAvailableError, TranscriptionError."""
```

`TranscriptionResult` — dataclass: `text`, `txt_path`, `json_path`, `language`, `duration_sec`, `segments`, `model`, `source_path`.

### FR-04. Загрузка и кэш модели

- Первый запуск: скачивание весов с Hugging Face (`Systran/faster-whisper-{size}`).
- Кэш: `~/.cache/huggingface/` (стандарт huggingface-hub).
- Повторные запуски: без повторной загрузки.
- Предупреждение `HF_TOKEN` — не ошибка; токен опционален для ускорения скачивания.

### FR-05. Зависимости Python

- `faster-whisper>=1.0`
- транзитивно: `ctranslate2`, `onnxruntime`, `av`, `huggingface-hub`

Установка: `pip install -r requirements.txt` в venv проекта.

### FR-06. Связка с этапом 1 (опционально v1.1)

```bash
python -m app process VIDEO [--language ru] [--model small]
```

Внутри: `extract_audio` → `transcribe_audio`; печать путей к WAV и transcript.

## 10. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Файл не существует | `FileNotFoundError` / exit 1 |
| Неподдерживаемое расширение | `ValueError` / exit 4 |
| Нет `faster_whisper` в venv | `ModelNotAvailableError` + текст «pip install -r requirements.txt» / exit 5 |
| Сбой загрузки модели (сеть, диск) | `ModelNotAvailableError` / exit 5 |
| Два параллельных `transcribe` | риск `.incomplete` в кэше HF — документировать «один процесс» |
| Прерывание Ctrl+C | процесс завершается; частичный transcript не сохраняется (v1) |
| Повреждённый аудиофайл | `TranscriptionError` / exit 5 |
